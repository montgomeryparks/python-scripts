# AGENTS.md

## Project Overview

This repository contains modular Python toolboxes for ArcGIS Pro, built via an AST-based bundler. Source `.py` scripts in `src/toolboxes/` are compiled into standalone `.pyt` files in `dist/` by `build_toolboxes.py`. Shared utilities live in `src/utils/` and are injected only when imported by tool scripts.

## Core Stack

- **Language**: Python 3.x
- **Runtime**: ArcGIS Pro (arcpy)
- **Package Manager**: pip (via `requirements.txt`)
- **Linter/Formatter**: ruff (importStrategy: fromEnvironment)
- **Testing**: pytest
- **Build**: `python build_toolboxes.py` — AST bundler that groups `.py` files by folder, resolves `src.utils` dependencies, and outputs `.pyt` into `dist/`
- **CI/CD**: GitHub Actions (`.github/workflows/build-toolboxes.yml`) builds and releases on `main` push

## Key Commands

- **Install**: `python -m pip install -r requirements.txt`
- **Dev server**: N/A — this repository contains ArcGIS Pro toolboxes, not a web server
- **Lint**: `ruff check .`
- **Format**: `ruff format .`
- **Typecheck**: `ruff check . --select=TRY401,FURB150,UP006` (ruff's built-in checks; no mypy/pyright config)
- **Unit Tests**: `python -m pytest tests/ -v`
- **Single Test**: `python -m pytest tests/ -v -k "<pattern>"`
- **Build Toolboxes**: `python build_toolboxes.py`
- **Clone ArcGIS Pro Env** (VS Code task): Run task **"1. Setup: Clone ArcGIS Pro Env"** from the Command Palette (`Ctrl+Shift+P`)

## Architecture & Directory Layout

- `src/`: Source code root
  - `src/toolboxes/`: Each subfolder becomes a single compiled `.pyt` file. Tools must be classes extending an object pattern with `getParameterInfo` and `execute` methods. These are the only scripts the build process compiles.
  - `src/utils/`: Shared utility modules (e.g., `auth.py`, `data_conversion.py`, `constants.py`). These are **dynamically injected** into `.pyt` files only when a tool explicitly imports from `src.utils`. The bundler resolves dependencies at the module level and includes only the utilities required by each toolbox.
  - `build_toolboxes.py`: The AST-based bundler script. Do not modify the build logic manually; instead, adjust tool scripts or utilities and re-run the build.
- `dist/`: Compiled `.pyt` outputs. **Never edit files in this directory manually** — they are auto-generated by `build_toolboxes.py` and gitignored.
- `helpers/`: Standalone Python scripts (currently none; previously `FeatureService_Azure_Helper.py`). These are **never** compiled into `.pyt` toolboxes and are for administrative/data engineering tasks only.
- `tests/`: PyTest integration tests using a dummy geodatabase. Tests exercise the tool classes in isolation.

## Coding Conventions & Gotchas

- **Parameter formatting**: Enforce leading commas in `arcpy.Parameter()` definitions and dictionary/keyword arguments (see `.github/templates/tool_template.py` and `.github/prompts/new_tool.prompt`).
- **Import strategy**: Ruff uses `fromEnvironment` — always develop within the Conda environment (`da_env` or `arcgispro-py3`) so imports resolve correctly.
- **API bearer parameters**: Treat API `bearer` tokens as static client keys, not dynamic session tokens.
- **Time-series column syntax**: When referencing time-series or project sequence data, the column name must be exactly `'Timeline'`.
- **Cursor cleanup**: Always clean up `arcpy.da.InsertCursor`, `UpdateCursor`, and `SearchCursor` objects using `with` blocks or explicit `del` statements to prevent ArcGIS schema locking errors.
- **Data transformations**: Prefer pushing data to DuckDB in-memory for heavy transformations rather than executing row-by-row updates via `arcpy`.
- **Geometry handling**: When mapping assets in the UI, do not filter out unlinked items; highlight them with a visual glow (project standard from `.github/prompts/new_tool.prompt`).

## Agent Boundaries & Restricted Files

- **Do not edit `dist/` manually** — these are generated `.pyt` artifacts. Rebuild by running `python build_toolboxes.py`.
- **Do not modify `.pyt` files directly** — they are auto-generated outputs. Edit the source `.py` scripts in `src/toolboxes/` instead.
- **Do not move or rename `src/utils/` modules** without updating all dependent tool scripts, as the bundler resolves utilities by exact module name. If a utility is renamed, re-run the build and check for missing imports.
- **Do not check in `.pyt` files** — `dist/` is gitignored; they are published as release assets via the GitHub Action.
- **Do not modify `.github/workflows/build-toolboxes.yml`** unless adding new toolbox folders or changing the build pipeline. The workflow runs `python build_toolboxes.py` and publishes `dist/*.pyt` as release assets.
- **Do not add new dependencies to `requirements.txt`** without confirming they are not already available in the ArcGIS Pro Conda environment. Prefer using only `arcpy`, `pandas`, `requests`, and `shapely` (all pre-installed in ArcGIS Pro Python environments).
- **Test files in `tests/`** exercise tool classes against a dummy geodatabase. Do not modify test database schemas without updating corresponding tool scripts.
